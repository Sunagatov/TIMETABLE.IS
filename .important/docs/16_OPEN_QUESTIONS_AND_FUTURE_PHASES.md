# Open Questions and Future Phases

## Open questions

These are not blockers for current replacement docs, but they remain good future clarification targets.

### 1. Frontend information architecture
The backend surfaces are clearer than the current frontend structure. UI grouping and page hierarchy may still need a dedicated design pass.

### 2. Topic hierarchy UX
The backend supports nested topics, but the ideal editing and navigation UX still deserves explicit design docs.

### 3. AI prompt/version management
Current repo surface reveals AI endpoints and contracts but not full prompt/version lifecycle documentation.

### 4. Progress semantics
Knowledge levels are clear numerically, but the human-facing wording for each level could be documented more explicitly later.

## Future phase ideas
- richer frontend docs with wireframe-level precision
- explicit API examples per route
- migration rules for schema evolution
- prompt management documentation
- automated contract tests for critical API surfaces
